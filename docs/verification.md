# Verification: 0.6.1

Tested locally on Minecraft 1.21.1 and NeoForge 21.1.265.

## Server checks

The JUnit supply-clock and deterministic-random tests pass. All 27 required NeoForge GameTests pass with the locked server mods. They cover shared delivery cycles and tier state, paused clocks, late-join countdowns, held-roll stability and population independence, cumulative item eligibility, genuinely different new-world seeds, saved membership and offline swap metadata, inventory capacity and overflow, market travel and damage rules, merchant stock, cooking, native structure generation and caches, and the sandbox gameplay loop. The compatibility test verifies that absent-wood Ex Deorum items cannot roll while normal sieves, meshes, barrels and crucibles remain eligible.

The client also checked the final EMI index for unsupported wood/metal integrations and unpowered electrical parts. The supported Ex Deorum item models have textured particle sprites.

A fixed 6,000-roll sample checks that resources stay close to 45% and decorative variants close to 5%, with useful stack quantities. Higher-tier samples must regularly produce advanced entries. This verifies distribution behavior, not whether every player will like every find.

The manual-processing test places an actual Ex Deorum sieve and runs its native sifting logic on gravel. It produces iron ore chunks without Create. The cooking test uses a real heated Farmer's Delight cooking pot. Resource IDs and recipes are validated against the installed jars.

Market tests include native powered Create drills with an unclaimed control, contraption assembly with an ordinary-block control, and pistons. The original market mask is protected even when the machinery is inside the same OPAC claim. Ordinary bridges beside the original footprint remain allowed. The cache test checks its sealed period, non-empty loot, successful team claim and absence of repeat win farming.

## Client and visual checks

A disposable world created through Minecraft's actual world-creation screen loaded with the intended preset. The real client driver checked random assignment, preserved membership on login, operator swapping and cleared beds, friendly-fire flags, Create recipes in EMI, 30-second deliveries, native merchant scrolling and payment, instant travel, the shop doorway, community-chest deposits and withdrawals, and public-kitchen access.

Screenshots were inspected at GUI scales 2 and 4, with shaders on and off. Armour plus extra absorption hearts were equipped. The delivery text uses NeoForge's actual health/armour/air layout heights and reserves room for the selected-item name. A focused visual pass visited a large island generated by the native seeded structure system. The supplied landmarks retain their native connected pieces; no new island geometry was authored. The Moog generation test finds ten starts across eight variants, and a seven-piece diorite island builds more than 73,000 blocks with sixteen containers. Screenshots also inspect an actual large Moog island.

A focused real-client respawn test passed after removing respawn delays. First and repeat enemy-base deaths both leave the native Respawn button available. Enemy-base deaths mark the returning raider; six-second respawn grace blocks incoming damage, ends on attack and then permits normal damage again. Server GameTests check quarter-speed mining only near the enemy base, normal home mining and timer expiry. Client mining prediction receives the same fatigue state from the server.

The safe-zone indicator is a subtle green screen-edge tint. It fades in on original market land and out on leaving; attached bridges remain ordinary PvP ground. Native damage tests check the land/bridge distinction. A separate rectangular hazard buffer and fall rescue remain active around the market. There are no physical boundary blocks or floating labels.

A focused HUD regression pass keeps the native selected-item label active while capturing screenshots, rather than waiting until it disappears. It checks requested GUI scales 2 and 4 at a window large enough to support both, plus no armour, armour with absorption hearts, underwater air bubbles and a simultaneous native action-bar message. The display renders after the native item-name layer and reserves only the space that is occupied; later native messages stack above it.

## Updating existing play

The updater requires Minecraft in the target profile to be closed. It locks and backs up supported skyblock saves before changing their generator metadata. The additional Ember and Moog structure sets are enabled for newly explored chunks; existing blocks, inventories and faction data are retained. Old unopened loot tables gain the new rewards. The one-time island migration does not refill any existing container, including a looted or player-placed chest.

The 0.4.0 personal progress migration uses the highest saved delivery count for the new shared clock, rather than summing the roster. Keybinds, video settings and existing shader/EMI preferences are retained. Exported packs contain no played saves, personal options or launcher/account databases.

## Limits

A full multi-session campaign with 4-12 friends has not been playtested. Long-term resource economy, event frequency and how much local mining fatigue changes repeat raids remain playtest questions. Homes remain raidable after the opening truce. Repeat-raid restrictions are a deterrent, not complete protection from indirect machinery, unowned hazards or extreme native Chance Cubes events. Existing terrain cannot acquire large structures without exploring new chunks.

## 0.6.0 update checks

The locked pack now includes Mouse Tweaks, 3D Skin Layers, AmbientSounds, Seamless Sleep and Subtle Effects, with CreativeCore, YACL, Fzzy Config and Kotlin for Forge. Every file comes from its official Modrinth CDN and has pinned hashes. The existing manual Ex Deorum route remains installed. Seamless Sleep's internal sleep barrier is excluded from random drops.

The final server run passes 27 required GameTests and the JUnit tests. New checks cover melee and arrows during the opening truce, expiry, home access, first and repeat raid-death timers, destructive-item restrictions with water and building-block controls, and direct block edits to protected market terrain. A genuine server Level.setBlock call is refused on protected foundation blocks while an ordinary nearby edit succeeds. Native Chance Cubes load 166 normal and 19 giant rewards, alongside nine custom dispatchers for 32 custom outcomes. Repeating installation leaves both pool sizes unchanged.

The full real-client pass succeeds with all five additions: world creation, assignment and saved teams, EMI compatibility, supported Ex Deorum textures, merchant scrolling and purchases, travel, the community chest and kitchen. A focused HUD pass captures selected-item labels, action-bar messages, armor, absorption hearts and air at actual GUI scales 2 and 4. Screenshots were inspected. The truce is top-left, away from Jade and native boss bars; delivery text stacks with the native HUD.

A further disposable-world check triggers the native redstone-and-diamond reward on a real starting island and sleeps through the smooth transition. Shared progression advances only 200 ticks during the test, rather than jumping with the daylight change. The first sleep fixture could not enter bed; enabling daylight cycling and clearing nearby monsters fixed the fixture. Final configuration loading has no missing-field deserialization warnings. Complete generated configs preserve the selected quieter values.

The new preparation period reads existing shared progress, so old saves do not restart it. No config-version migration rewrites existing settings. The local updater compares existing preferences and saves before and after the install; its result is retained under .tools for this machine. Fresh imports receive the quieter defaults; existing files remain theirs to customize.

Long-term multiplayer balance and subjective audio levels still need ordinary playtesting. One deterministic native reward and direct world-edit protection do not establish that every possible upstream destructive reward obeys every market or truce rule.

## 0.6.1 release checks

0.6.1 changes packaging only; gameplay code, mods and configs match 0.6.0. The release JAR was rebuilt with the Gradle wrapper on Temurin 21. The 8 JUnit tests and all 27 required GameTests pass on the final code.

The core mod is now an ordinary `files` entry in the pack index instead of a JAR in `overrides/mods`. `scripts/package_pack.py` writes `dist/Random-Item-Skyblock-0.6.1.mrpack-template`; `publish/upload.py` replaces only that entry's URL with the uploaded Modrinth file and checks that the uploaded hashes and size match. `publish/tools/check_mrpack.py` downloaded all 40 third-party entries from their URLs and matched every size, SHA-1 and SHA-512; the core entry matched the local JAR. `scripts/verify_distribution.py` passes.

The server zip no longer needs Python. On this Windows PC, with no Java on PATH and no JAVA_HOME, `START-SERVER.cmd` was run in a fresh empty folder. It asked for the EULA, downloaded and verified a portable Temurin 21 runtime, 31 server mods and the NeoForge installer, installed NeoForge and reached `Done` in about 67 seconds. A second start skipped all downloads and reached `Done` in 16 seconds. Declining the EULA exits before downloading anything and writes no `eula.txt`. `start.sh` was run under Git Bash with an existing Java 21. It handled EULA refusal and acceptance, verified the downloads and installed NeoForge; the final launch needs a real Linux or macOS machine. The four pinned Linux and macOS Temurin archives were downloaded, matched their SHA-256 values and have the `bin/java` layouts the script expects.

The gallery screenshots were captured from the real pack with Complementary Reimagined through `GallerySmoke`, a development-only client driver that is excluded from the release JAR.
